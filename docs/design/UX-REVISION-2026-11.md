# OpenScale — UX revision, 20 ноября 2026

## Назначение

Первая прямая реализация принципов новой покупательской концепции. Это ограниченная UX-итерация, а не финальная приёмка дизайна: сборка и UI-тесты должны быть выполнены в окружении проекта с Rust/Slint toolchain, затем интерфейс нужно проверить на физическом дисплее 1024×768.

## Принципы

- Основной путь остаётся `категории → товары → взвешивание → этикетка`.
- Покупательские элементы используют текстовые названия вместо неоднозначных пиктограмм.
- Цвета категорий нейтрализованы; визуальный акцент зарезервирован для выбранного товара и состояний.
- Название товара обязательно отображается в карточке.
- Сетка сохраняет две строки карточек над нижней информационной зоной.
- Нижняя зона показывает выбранный товар, цену, текущий вес, сумму и действие печати без отдельного модального окна.
- После подтверждения печати нижняя зона сохраняет контекст товара и точный снимок веса/суммы, по которому запускается печать.
- Неизвестный результат печати остаётся блокирующим и явно предупреждает не повторять печать до проверки лотка.
- Поиск доступен по текстовой кнопке и возвращает пользователя в исходный контекст.

## Покупательский экран

### Главный экран категорий

- Категории используют нейтральную поверхность вместо индивидуальных насыщенных цветов.
- Название категории остаётся главным текстовым идентификатором.
- Нижняя полоса всегда резервируется под кнопку «Найти товар»; кнопки перелистывания появляются только при нескольких страницах.

### Каталог товаров

- По умолчанию используется 7 колонок; настройка ограничена диапазоном 4–8.
- Карточки товара имеют одинаковую структуру: изображение, обязательное название, цена.
- При наличии цены по карте обе цены показаны в компактном текстовом виде.
- Название категории показано в шапке каталога рядом с кнопкой «Категории».
- Внизу зарезервирована панель высотой 176 px; товары не прокручиваются и не рисуются под ней.
- На странице остаются две строки карточек. При 7 колонках ёмкость — 14 позиций вместе с элементами навигации.

### Нижняя информационная зона

До подтверждения показывает:
- изображение (если оно есть), название и цену;
- цену по карте (если есть);
- текущий вес и причину, по которой вес ещё не готов;
- рассчитанную стоимость;
- отмену и печать.

После подтверждения сохраняет:
- актуальные название и цены, перечитанные из базы;
- тот же зафиксированный вес, который используется при печати;
- рассчитанную сумму;
- состояние печати и понятную инструкцию покупателю.

Точный вес и суммы записываются в свойства панели непосредственно из подтверждающего снимка, а не остаются от предыдущего 100-мс UI-тика.

### Поиск

- Кнопка поиска подписана «Найти товар».
- Виртуальная клавиатура использует подписи «Пробел» и «Удалить».
- Возврат из поиска ведёт на исходный экран.
- Если поиск открыт из каталога, исходная страница и список товаров восстанавливаются.

## Административная часть

Сохранена структура из шести разделов:

1. Интерфейс
2. Весы
3. Этикетки и принтер
4. Сеть и обмен
5. Отчёты и журнал
6. Обслуживание

Переходы категорий и существующие обработчики не переписывались в рамках этой итерации. Удалена только пользовательская настройка скрытия названия товара: название теперь обязательная часть карточки. Старое поле `card_show_name` пока сохраняется в формате импорта/экспорта для совместимости со старыми файлами конфигурации, но больше не влияет на текущий интерфейс.

## Изменённые исходники

- `app/openscale/ui/main.slint` — нейтральные плитки категорий, обязательные названия товаров, карточки и нижняя панель, текстовые действия, визуальное состояние выбора, сохранение контекста товара после печати.
- `app/openscale/src/flow.rs` — 7-колоночный режим по умолчанию (через TradeSettings), двухрядная раскладка, возврат поиска в исходный контекст, восстановление списка категории, фиксация значений панели по тому же снимку, что идёт на печать.
- `app/openscale/src/tiles.rs` — резервирование области поиска на главном экране и тесты пагинации товарной сетки.
- `app/openscale/src/cfgio.rs` — значение по умолчанию 7 и диапазон 4–8 для числа колонок; старое поле `card_show_name` сохраняется в формате файла.
- `app/openscale/src/main.rs` — значение по умолчанию и ограничение числа колонок; удалена привязка удалённой настройки видимости названия.
- `app/openscale/src/context.rs` — удалено неиспользуемое runtime-состояние `card_show_name`.
- `app/openscale/src/settings.rs` — удалена настройка скрытия названий; исправлен размер массива защитных admin-команд; импорт конфигурации применяет число колонок в runtime.
- `app/openscale/src/ui_tests.rs` — добавлены проверки возврата из поиска в исходный каталог и сохранения точного веса/суммы подтверждения.

## Важные ограничения проверки

В среде подготовки этой итерации отсутствуют `cargo`, `rustc`, `rustfmt` и Slint compiler. Поэтому здесь выполнена проверка исходников и связей, но не выполнены `cargo fmt`, `cargo test --workspace`, `cargo clippy` и release-сборка. Нельзя считать эту итерацию готовой к развёртыванию до выполнения этих команд в штатном окружении проекта.

Нужна обязательная проверка на физическом устройстве:

1. Читаемость карточек и цен с обычного расстояния.
2. Точность касаний по карточкам в 7- и 8-колоночных режимах.
3. Отсутствие перекрытия каталога нижней панелью.
4. Проверка длинных названий и цен по карте.
5. Поиск из главного экрана и из каталога с возвратом на исходную страницу.
6. Переключение товара, отмена, нестабильный/малый вес и отключение весов.
7. Печать: статус выполнения, выдача этикетки, достоверная ошибка и неопределённый результат без повторного задания.
8. Доступность всех административных разделов и сохранение ограничений ролей.

## Следующий критерий приёмки

Сначала выполнить `cargo fmt --check`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings` и release-сборку в штатном окружении. После устранения возможных ошибок — снять реальные фотографии/скриншоты всех состояний 1024×768 и провести тесты с покупателями. Число колонок, размеры шрифта и визуальные акценты пока являются обоснованными начальными параметрами, но не результатом полевого UX-эксперимента.
